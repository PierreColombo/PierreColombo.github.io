0. En une phrase

Audit expert de 6 benchmarks de physique : sur 250 réponses rejetées auditées, 95,2 % des rejets ne sont pas des erreurs du modèle (57,2 % items défectueux, 38,0 % erreurs de correcteur, 4,8 % erreurs de modèle) ; après exclusion/réparation, les scores passent p.ex. de 47,3 % à 78,7 % (GPT-5.6-Sol, HLE-Physics, mean@4) [Abstract, §5, Tab. 3].

Claim principal, formulé précisément : sur des questions fermées, text-only, à réponse finale vérifiable, le taux d'erreur réel des modèles frontière est désormais inférieur au taux de défaut des benchmarks, donc l'essentiel de l'erreur mesurée est celle du benchmark, pas du modèle [§Discussion]. Corollaire que les auteurs assument : « Frontier models are not failing these physics problems. The benchmarks are failing to pose them. » [§Discussion].

⚠️ Nuance que le titre/abstract écrasent : la majorité stricte n'est pas « erreur de correcteur » (38,0 %) mais « erreur de benchmark » — énoncé ambigu ou solution de référence fausse (57,2 %) [Tab. 3]. Les erreurs de correcteur ne sont majoritaires que là où l'évaluateur est rule-based : PHYBench 71,43 %, PRISM-Physics 64,86 % [Tab. 3, Fig. 2].

1. Tâches & data (ici : données de l'audit)

  • Origine des tâches : aucune tâche créée. Six benchmarks existants, répartis en deux groupes selon la provenance [§2.1.1] :
  • sources publiques (risque de contamination assumé) : UGPhysics (undergrad), PHYBench (jusqu'à olympiade), PRISM-Physics (avancé) ;
  • expert-authored : HLE-Physics (subset physique de HLE), CMT-Benchmark (matière condensée théorique), CritPt (frontière de la recherche).
  • Pipeline d'audit, étape par étape [§2, §2.3, App. B, App. D] : 1. éval pré-audit avec les matériaux et l'évaluateur d'origine (CMT n'a pas d'évaluateur public → pipeline HLE adapté) ; 2. run de collecte d'audit séparé du run de scoring, pour réduire la charge experte : on ne retient que les questions rejetées sur toutes les tentatives de GPT-5.6-Sol High ; 3. attribution par un expert du sous-domaine en 3 classes (benchmark / grader / model error) ; 4. correction : exclusion des questions défectueuses (HLE, PHYBench, PRISM, UG) ou réparation (CritPt, CMT) ; 5. réévaluation de tous les modèles sur les sous-ensembles retenus, avec un pipeline commun adapté de HLE (system prompt + judge prompt de HLE) [§3].

2. Environnement / harness (ici : harness d'évaluation)

  • Observation : single-turn question → réponse finale. Tous les items sont closed-ended avec une réponse finale de référence ; la dérivation n'a pas à suivre un chemin prescrit, toute forme mathématique équivalente est acceptable en principe [§2.1.1].
  • Outils [App. A] : sur les benchmarks public-source, tous les modèles sans outils. Sur les expert-authored, GPT-5.6-Sol via Codex et Fable 5 via Claude Code, outils activés ; Gemini 3.1 Pro sans outils partout. Reasoning effort High par défaut, Max pour GPT-5.6-Sol sur CritPt. Signature des outils : non précisée.
  • Multi-turn / horizon : non applicable (une réponse par tentative ; HLE et PHYBench autorisent jusqu'à 5 tentatives dans le run de collecte d'audit seulement).
  • Exécution / déterminisme : non précisé (pas de température, pas de seed, pas de version d'API).
  • Gestion des sorties mal formées : 19 questions PRISM écartées pour « formatting or data-loading issues » [App. B.1.2] ; rien sur les réponses mal formatées côté modèle.
  • Exemple de trajectoire : aucune trajectoire complète ; seulement des paires (réponse finale du modèle, réponse de référence), dérivations omises [App. C, App. E].

⚠️ Le harness n'est pas constant entre pré-audit et corrigé (voir §7.0) : sur PHYBench/PRISM/UG l'évaluateur change (rule-based → juge LLM adapté de HLE) en même temps que les questions défectueuses sont retirées. Seul CMT-Benchmark garde le même évaluateur avant/après : « The same HLE-adapted evaluator is used before and after correction. The corrections are to the benchmark materials only. » [§4.2.2]. C'est le seul contraste propre du papier.

3. Reward / vérifieur — cœur du papier

  • Types de vérifieurs audités [§2.1.2, §5, App. B] :
  • rule-based symbolique : PHYBench, via Expression Edit Distance (EED). Les auteurs écartent délibérément le score partiel EED et exigent EED = 100 pour « correct », au motif que le crédit partiel masque les rejets d'expressions équivalentes [App. B.1.1] ;
  • rule-based + juge LLM auxiliaire : UGPhysics (SymPy + juge optionnel). Les auteurs remplacent le juge d'origine gpt-4o-2024-08-06 par un modèle frontière pour améliorer la reconnaissance d'équivalence [App. B.1.3] ;
  • juge LLM : HLE (system prompt + judge prompt d'origine), réutilisé/adapté pour CMT (qui n'a pas d'évaluateur public) et pour toutes les évaluations corrigées [§3] ;
  • boîte noire : CritPt — l'interface ne rend que des scores agrégés, pas de jugement par question, donc aucune erreur de correcteur n'y est imputable [App. B.2.3].
  • Granularité : binaire (accuracy) partout après la décision des auteurs d'écarter le crédit partiel EED. Métriques : mean@4 (moyenne sur 4 tentatives) et pass@4 ; pré-audit CritPt = mean@5 d'Artificial Analysis [§3].
  • Fiabilité mesurée du vérifieur : oui, partiellement — c'est le résultat central. Taux d'erreur de correcteur mesuré sur les rejets : EED/PHYBench 71,43 %, PRISM 64,86 %, SymPy+juge/UGPhysics 13,64 %, juge HLE 4,08 %. Les auteurs affirment que le pipeline HLE « has the lowest grader error rate of all the evaluators we audited (4,08 %) » [§3]. ⚠️ Trois limites majeures, de mon fait : 1. mesure unilatérale — l'audit ne porte (sauf CMT/CritPt) que sur les réponses rejetées, donc ne détecte que les faux négatifs du correcteur. Les faux positifs (réponse fausse acceptée par un juge complaisant, ou acceptée par chance/contamination) ne sont jamais mesurés. Le 4,08 % du juge HLE est donc une borne sur un seul type d'erreur, sur 4 cas /98 ; 2. le juge HLE sert à la fois de mesure et de correctif — il est l'évaluateur de toutes les évals corrigées, et son propre taux d'erreur a été estimé avec ce même protocole ; 3. aucune validation du juge contre les humains au sens habituel (accord juge↔expert sur un échantillon équilibré) : il n'y a pas de table d'accord, pas de κ.
  • Si juge LLM : modèle juge = non précisé explicitement, « High reasoning effort for both answer generation and LLM judging » [App. A] ; prompts = ceux de HLE, non recopiés en annexe (renvoi à phan2025lastexam). ⚠️ Pour un papier dont tout le résultat dépend du juge, ne pas publier le prompt est une faiblesse de reproductibilité.
  • Robustesse / hacking : le vérifieur n'a pas été attaqué ni testé contre le reward hacking. Mais le papier documente la fragilité symétrique : la métrique rule-based rejette des réponses correctes, le juge LLM introduit ses propres biais (position, verbosité, faible accuracy sur le raisonnement objectif — litt. citée [§5]).
  • Fiabilité de l'audit lui-même (le « vérifieur du vérifieur ») [App. D.2] :
  • revue non aveugle : les reviewers voient énoncé + solution de référence + réponse du modèle + une pré-revue générée par IA ;
  • 446 annotations / 250 questions : 196 doublement relues, 54 une seule fois (« due to limited human resources ») ;
  • accord brut sur les items doublement relus : 140/196 = 71,43 %, 56 désaccords (28,57 %), tous tranchés par une 3ᵉ revue. Désaccords dominants : benchmark↔grader 34, benchmark↔model 19, grader↔model 3 [Tab. 5] ;
  • sur CritPt/CMT, protocole différent : un seul reviewer par problème, invité à esquisser sa propre approche avant de lire la solution de référence, autorisé à utiliser des outils IA, et chargé de produire lui-même la solution de référence quand l'originale est indisponible (CritPt) [App. D.1]. ⚠️ Donc : audit non aveugle, 21,6 % des items à un seul relecteur, bruit d'étiquetage inter-annotateur (28,6 %) six fois plus grand que la quantité mesurée (part d'erreur modèle, 4,8 %). Et sur CritPt la vérité terrain corrigée est dérivée par les mêmes personnes qui jugent ensuite le modèle (circularité).

4. Optimisation

Non applicable : aucun entraînement, aucun RL, aucun hyperparamètre d'optimisation. Les seuls réglages sont l'effort de raisonnement (High/Max) et le budget de tentatives (4 ou 5) [App. A].

5. Failure modes — typologie des défauts (transposée du reward hacking)

Ce que le papier catalogue, ce ne sont pas des failure modes de politique mais de vérifieur et de données. Typologie, avec exemple → détection → correction :

A. Erreurs de correcteur (le modèle a raison, l'évaluateur dit non) [§4 Fig. 3, App. C.2] 1. Dénominateur non rationalisé : P/(3√6) vs (√6/18)P — EED 0,0, score binaire 0 [Fig. 3, PHYBench pb 140]. 2. Ordre des facteurs : 5mRω² vs 5mω²R — EED 0,0 [App. ex:grader-phy]. 3. Réécriture triviale : (bV₀/m)t vs bV₀t/m ; note du relecteur « The two responses are identical » [App. ex:grader-prism]. 4. Équivalence dans la limite demandée + convention de signe : réponse du modèle F(x) = -(3E(0)x/n²ℓ²)·exp(3x²/2n²ℓ²), référence 3E(0)x/(nℓ)² ; identiques à petit x, au signe (attraction vs module) près — score binaire 0 [App. ex:grader-hle]. ⚠️ Celui-ci est un cas limite : l'équivalence n'est vraie que dans la limite, et le juge aurait pu légitimement hésiter. → Correction : remplacer l'évaluateur rule-based par le juge LLM du pipeline HLE.

B. Erreurs de benchmark (l'item est cassé) [App. C.1] 1. Référence identiquement nulle : l'expression de référence PHYBench pour u_min se simplifie en 0 ; note : « Reference answer equals 0, which is incorrect ». 2. Question sous-déterminée : PRISM, temps de vol d'un électron à choisir parmi 3 valeurs sans aucune donnée de distance ni de vitesse ; « Not enough information is given in the problem ». 3. Énoncé qui ne dit pas ce qu'il veut : UGPhysics, amortissement critique — « Perhaps the question meant "without overshoot", but it didn't state that ». 4. Arithmétique fausse dans la référence : HLE, référence −√2 au lieu de 2−√2, algèbre correcte mais arithmétique finale fausse. 5. Convention/normalisation non fixée : CritPt 44 (Kitaev honeycomb), le hamiltonien n'est pas écrit → σ vs S = σ/2, énergies différant d'un facteur 4 → réponse numérique non définie [Fig. 4]. 6. Hypothèses manquantes dans un QCM : CMT pb 31 — dimension d'espace, comptage des liens, corrélateur connexe vs ordinaire, restriction g = 0 ; après réparation la réponse de référence change (a;c → a;b;c) et devient celle du modèle [Fig. 5]. → Correction : exclusion (HLE/PHYBench/PRISM/UG) ou réparation de l'énoncé + de la référence (CMT 29 réparées/1 exclue ; CritPt 19 réparées/2 exclues).

C. Vraies erreurs de modèle qui subsistent [App. E] - CritPt 18 : les 4 tentatives supposent les polarisabilités réelles alors que l'énoncé ne l'impose pas → cos(kd₀) au lieu de Re[α₁α₂e^{ikd₀}] ; cas particulier présenté comme général. Failure mode intéressant et très transférable : hypothèse implicite non justifiée qui rend la réponse localement cohérente. - Les auteurs rapportent aussi, sans chiffres, que des harnesses agentiques de type « conjectures ouvertes en maths » appliqués à des problèmes ouverts de physique « make considerably less progress », et aucun problème ouvert n'a été résolu [§Discussion]. C'est un contrepoids explicite à la saturation annoncée.

Mécanisme général, argumenté §5 et §Discussion : un correcteur défectueux se trompe surtout en rejetant des solutions correctes ; quand le modèle est faible il en produit peu, le score mesuré reste proche du vrai. À mesure que la capacité monte, les bonnes réponses deviennent fréquentes, les erreurs du correcteur s'accumulent, et l'écart mesuré/vrai se creuse. Le taux d'erreur mesuré d'un modèle ne peut pas descendre sous le taux de défaut du benchmark. C'est le point théorique à retenir.

6. Infra & coût

Pas d'infra de rollout. Coût de l'audit : non précisé en heures ou en dollars. Seuls proxys : 446 annotations pour 250 items, quota de 30 reviews/contributeur, ~38 auditeurs, 12 advisors [App. D.2, Author Contributions]. ⚠️ C'est l'information la plus utile qui manque : le prix d'un audit expert de 250 items est exactement ce qu'un praticien a besoin de budgéter.

In-distribution vs OOD, transfert

Pas de notion de train/test ici. Transfert inter-benchmarks du diagnostic : oui, le papier montre que le même type de défaut apparaît dans 6 benchmarks indépendants, et cite une réplication externe partielle (Anthropic, CritPt-Corrected, 31/71 énoncés révisés, mean@16 88,4 % pour Fable 5.1) [§Discussion, App. B.2.3], plus l'analogie SWE-bench : audit de 138 tâches SWE-bench Verified → problèmes matériels dans 59,4 %, et ~30 % des tâches SWE-bench Pro cassées [§5, citations openai2026swebenchverified/pro]. ⚠️ Ces deux derniers chiffres sont cités, pas mesurés ici.

Ablations

  • Pas d'ablation séparant (i) exclusion des questions défectueuses de (ii) changement d'évaluateur sur PHYBench/PRISM/UGPhysics — les deux interventions sont appliquées ensemble. Les auteurs écrivent explicitement que les comptes de la Tab. 3 « are not a reconstruction of the scores in Table 1 ».
  • Le seul contraste contrôlé : CMT-Benchmark, évaluateur identique avant/après, corrections limitées aux matériaux → +26,2 pts (61,00 → 87,24). C'est la preuve la plus propre que les matériaux seuls coûtent des dizaines de points.
  • Remplacement du juge gpt-4o-2024-08-06 d'UGPhysics par un modèle frontière : fait, mais pas chiffré (aucun before/after de ce seul changement) [App. B.1.3].
  • Choix EED = 100 au lieu du crédit partiel : justifié qualitativement, pas chiffré [App. B.1.1].

Scaling

Non étudié (3 modèles frontière, pas de variation de taille). Argument de scaling conceptuel : plus la capacité monte, plus la part des défauts dans l'erreur mesurée grossit [§5, §Discussion].

Solidité

  • ❌ baselines appariées : accès aux outils, effort de raisonnement, nombre de tentatives et évaluateur varient entre modèles et entre pré/post — aucune comparaison n'est appariée.
  • ✅ ablation : CMT isole l'effet « matériaux seuls » à évaluateur constant (1 benchmark sur 6, n = 50).
  • ❌ variance / seeds : aucune barre d'erreur, aucun IC, aucun seed ; n = 22 à 98 rejets par benchmark, et les parts d'attribution (ex. UGPhysics 13,64 % = 3/22) reposent sur de très petits comptes.
  • ✅ cohérence : chiffres de l'abstract tous retrouvés à l'identique dans src/results/*.tex et Tab. 1/3.
  • ❌ éval fiable : audit non aveugle (réponse du modèle + pré-revue IA visibles), accord inter-annotateur brut 71,43 % seulement, 54/250 items à un seul relecteur, vérité terrain CritPt auto-produite par les relecteurs, contamination jamais mesurée, faux positifs du correcteur jamais mesurés.
  • ❌ reproductibilité : ni code, ni sets corrigés, ni énoncés réparés, ni prompts du juge publiés — seulement quelques exemples en annexe.
  • ⚠️ échelle : 502 questions évaluées, 250 auditées, sur 6 benchmarks — suffisant pour le constat qualitatif, trop petit pour les parts fines.

Verdict : la direction est solide, la magnitude est à répliquer. Le fait central — l'essentiel des rejets sur ces benchmarks n'est pas imputable au modèle — est soutenu par trois signaux convergents (attribution experte, contraste propre sur CMT, réplication indépendante d'Anthropic sur CritPt) et par l'analogie SWE-bench. Les chiffres précis (47,3 → 78,7 ; 95,2 %) ne doivent pas être cités comme des mesures : ils mélangent exclusion de questions, changement de juge, outils et budget de tentatives, sans variance ni aveuglement. ⚠️ Le papier commet d'ailleurs, à son échelle, la faute qu'il dénonce : il mesure un correcteur avec un correcteur humain dont il ne valide pas la fiabilité (71,4 % d'accord).

Meilleur ingrédient à transposer : la décomposition à trois classes de l'erreur mesurée (défaut d'item / erreur de correcteur / erreur de modèle), appliquée aux rejets d'un modèle fort, avec double annotation et résolution des conflits. C'est peu coûteux, ça ne demande aucune infra, et ça produit directement le chiffre dont dépend toute interprétation d'un écart : le taux de défaut du benchmark. Le corollaire théorique à garder sous la main en réunion : le taux d'erreur mesuré d'un modèle ne peut pas descendre sous le taux de défaut du benchmark [§Discussion]. Dès que l'écart entre deux checkpoints est du même ordre que le taux de défaut, l'écart n'est pas un signal — et en droit, où le vérifieur est un juge ou une rubrique, il n'y a aucune raison d'espérer un taux de défaut plus bas qu'en physique (l'argument SWE-bench du §5 le dit pour un domaine qui, lui, embarque des tests exécutables : 59,4 % de tâches problématiques dans Verified après deux tours de curation).

Expérience minimale : prendre les ~150-250 items de Harvey LAB / Vals rejetés par le meilleur checkpoint Gemini actuel ; les faire auditer par des juristes du domaine, en aveugle sur l'identité du modèle et sans pré-revue IA (correction du défaut de protocole de ce papier), deux annotateurs par item, κ rapporté ; classer en défaut d'item / erreur de juge / erreur de modèle ; auditer aussi un échantillon apparié d'items acceptés pour estimer les faux positifs du juge. Résultat attendu, par extrapolation du papier et de SWE-bench : 30 à 60 % des rejets non imputables au modèle, dominés par l'ambiguïté d'énoncé et la pluralité des réponses défendables plutôt que par l'équivalence de forme. Livrable : un taux de défaut chiffré qui devient le seuil de détectabilité sous lequel aucun écart de post-training ne sera rapporté.

Question à poser en interne chez GDM : quel est le taux de défaut mesuré de Harvey LAB et de Vals Legal Research Bench, et l'accord juge↔avocat a-t-il été mesuré dans les deux sens (faux négatifs et faux positifs) ? Tant que ce chiffre n'existe pas, quelle est la règle d'équipe pour décider qu'un delta de post-training est réel — et avons-nous un jeu « LAB-Verified » audité, à geler, sur lequel comparer les checkpoints ?
